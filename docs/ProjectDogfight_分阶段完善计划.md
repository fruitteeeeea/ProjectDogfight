## 1. 目标与使用方式

围绕现有 2D 狗斗系统，把项目完善为操作易理解、战斗有选择、任务有变化、流程完整的手机游戏。Jet Lancer 是用户指定的玩法参考；本计划以当前项目能力为依据，不要求复制其素材、关卡或全部机制。

首轮交付范围：一个短教学、三种职责明确的敌机、三关不同打法的正式任务，以及首页、战斗、结算、暂停、成绩保存的完整流程。核心体验是取得攻击位置、保持攻击窗口、选择武器与加速时机、受到压力时脱离。

商城、复杂养成、联网排行榜、护航、大量新飞机与武器不进入首轮。不要用堆叠功能替代狗斗手感与任务设计。改善完成度不等于保证通过 App Store 审核；发布阶段需结合实际拒审原文复核。

### 后续 Codex 执行规则

1. 每轮先读取本文件及适用的项目指引，检查 Git 状态，保留用户已有修改。
2. 用户授权实施后，从最早未完成阶段开始；默认每轮只处理该阶段内一个可验证任务或紧密相关任务组，不自动扩展至后续阶段。
3. 实施前核对当前代码。下述项目问题来自静态阅读，未通过手机试玩确认；若现状已变化，先修正文档依据。
4. 将任务状态更新为“进行中”，完成代码与相关检查后追加实施记录。没有验证证据时，标记“待验收”，不要勾选完成。
5. 自动检查可以确认规则正确，手感、教学和设备体验必须记录实际试玩；无法运行时写明限制，并继续能独立完成的工作。
6. 每轮结束同步任务清单、阶段总览、实施记录与下一步。阶段验收通过后才进入下一阶段；用户明确调整顺序时记录原因。
7. 数值是可调起点，不是验收结论。不要为通过检查删除必要功能，也不要仅凭实现存在宣布体验完成。

状态使用：未开始 → 进行中 → 待验收 → 已完成；遇到外部依赖可标记“受阻”。任务勾选框仅表示已完成且有验证记录。部分完成保留未勾选，并在记录中写出剩余工作。

### P1：稳定战斗与游戏流程

目标：先确保一局游戏有明确开始与结束，再调整玩法。

- [ ] **P1-01 统一战斗状态。** 以游戏管理器集中管理准备、战斗、暂停、结算；刷怪、任务计时、伤害、武器输入、奖励和计分遵守状态。准备时无敌机攻击，不允许提前刷分；开始与结束调用可重复但只生效一次。正式版本不依赖测试无敌保护准备状态。 **状态：待验收，记录 R001。**
- [ ] **P1-02 修正刷怪与存活统计。** 生成器移出敌机组；只统计存活敌机；按剩余名额生成，考虑延迟添加中的对象；坠毁动画不占存活名额。进入准备或结算停止生成。 **状态：待验收，记录 R001。**
- [ ] **P1-03 固定结算结果。** 任务结束时保存本局结果快照，停止任务计时和战斗输入，禁止继续加分与发奖励。死亡与超时同帧只产生一个结果；玩家死亡优先判定失败。区分被击落与时间不足，并展示结果对应原因。 **状态：待验收，记录 R001。**
- [ ] **P1-04 补齐流程入口。** 提供暂停、继续、重试、返回首页；结算提供重试和返回首页。切后台进入暂停，返回前台后由玩家继续；清理按住状态，避免恢复后持续开火。重试重置时间倍率、计时、分数、敌机、奖励和控制显示。 **状态：待验收，记录 R001。**
- [ ] **P1-05 清理发布状态。** 将调试伤害、调试计分、GameSpeed 标签和三倍速按钮移出正式体验；开发工具可保留在明确的开发入口。同步检查触屏、键鼠和手柄在结算后均不能继续战斗。 **状态：待验收，记录 R001。**

验收：准备中等待 15 秒不发生战斗；正常开始、死亡、超时成功、超时失败均能结算；结算后等待 10 秒成绩固定；连续重试 5 次状态正确；暂停期间计时与战斗不推进；前后台往返不遗留按键。自动检查重点覆盖状态、刷怪上限、重复结束和成绩冻结。

### P2：打磨狗斗手感与手机操作

目标：玩家能主动取得攻击位置，也能通过操作摆脱压力。

- [ ] **P2-01 建立调参基准。** 用同一敌机与场景记录初始速度、转向、加速、武器参数，以及一次追击和脱离的试玩观察。飞行参数沿用现有数据资源，避免不同脚本重复硬编码。
- [ ] **P2-02 调整飞行关系。** 验证普通转向可以追击，加速可以追上或脱离；加速不能在所有场景中成为持续按住的最优解，通过已有持续时间、冷却或转向关系形成取舍。引擎开关只在作用明确、可教会时保留为主要手机按钮。
- [ ] **P2-03 明确武器职责。** 机枪承担持续瞄准攻击，导弹承担有限次数的高价值攻击；说明发射条件、命中方式、弹药与补充方式。先检查现有导弹是否有锁定机制，不凭空添加锁定流程；若有锁定，其状态必须可见。
- [ ] **P2-04 改善战斗可读性。** 统一敌我识别、屏外敌机方向、来袭导弹、受击、低血量和弹药反馈。攻击提示要留反应窗口；镜头震动、HUD 位移和音效不能遮蔽关键威胁。
- [ ] **P2-05 完善触屏布局。** 将字母按钮换成功能图标与简短说明，主要操作为转向、射击、导弹、加速；暂停入口固定。支持同时转向和射击/加速；关键按钮在安全区域内，并允许降低震动强度。

验收：记录至少三轮相同遭遇的前后对比；试玩者能说明什么时候追击、发射导弹和脱离；没有长时间无法取得攻击位置的绕圈僵局；多点触控不抢占、不粘连。手感结果标记为待人工验收，不能用脚本测试替代。

### P3：建立教学与敌机职责

目标：让新玩家逐步学会 P2 确定的操作，并看懂不同敌机。

- [ ] **P3-01 制作短教学。** 顺序为转向到指定方向、击落弱威胁目标、使用导弹、使用加速脱离、综合交战；按实际操作完成推进，不靠读完文字或等计时推进。教学可重玩、可跳过，失败可重试当前步骤。
- [ ] **P3-02 配置三种敌机。** 普通型用于基础追击，追击型持续施压，重装型血量高且转向较慢。优先复用现有飞机与行为树，通过独立配置区分，不先增加新武器系统。
- [ ] **P3-03 建立识别与公平性。** 三种敌机有可辨认的轮廓、标记或颜色组合，不能只靠颜色识别；首次登场简述职责。生成位置不与玩家重叠，不在出现瞬间造成不可避免的伤害；重装目标仍可被机枪击落。
- [ ] **P3-04 完成入门试玩。** 邀请至少一名未接触项目的玩家，不做口头解释，记录卡住步骤、误触、失败原因和完成情况；修改后再次验证。

验收：玩家独立完成教学并理解四个主要操作；能够识别三类敌机并说明优先处理对象。无人试玩时保持 P3-04 待验收，并明确所缺证据。

### P4：首组三关与任务节奏

目标：用有限内容验证不同打法，而非复制积分挑战。

- [ ] **P4-01 建立关卡数据与入口。** 使用稳定关卡 ID、显示名称、任务说明、目标类型、时间、波次、敌机配置、生成方向、补给与评级配置；复用同一战斗场景。关卡开始前显示目标，HUD 显示当前进度；重试使用同一关卡配置。
- [ ] **P4-02 实现三种任务规则。** 击落指定数量、生存到时间结束、击落指定目标组；任务逻辑与 HUD 分离。目标 ID 区分必杀目标和普通护卫；关卡胜负通过 P1 的统一结束入口产生。
- [ ] **P4-03 配置三关。** 按下表制作，固定初版参数；后续调参必须记录版本与依据。波次按任务安排，不沿用不受控的永久自动刷怪。
- [ ] **P4-04 验证节奏与差异。** 完整游玩三关并记录遇敌等待、完成时间、失败原因、武器使用和补给选择；若打法相同，先修改目标或组合，再增加内容。

| 关卡 | 初版配置 | 主要打法 |
| --- | --- | --- |
| L01 初次交战 | 90 秒内击落 6 架普通敌机；两波各 3 架，上一波清除后进入下一波 | 主动追击、保持机枪攻击位置 |
| L02 突围 | 生存 60 秒；开场 2 架追击型，20 秒后加入 2 架普通型，40 秒后加入 1 架重装型；中途出现一次维修补给，无无限补刷 | 脱离压力，选择是否冒险拿补给 |
| L03 重装拦截 | 90 秒内击落两架指定重装目标；每波 1 架目标与 2 架普通护卫；该波全部清除后进入下一波；第二波前提供武器补给 | 选择优先目标，管理导弹与攻击窗口 |

评级与通关分开：通关依据任务目标，不再依赖积分阈值。初版均采用 C/B/A；击落类任务按剩余时间占任务时限的比例评级（不足 25% 为 C，25% 至不足 50% 为 B，50% 及以上为 A）；生存关按结束时血量占最大血量比例使用同样阈值。失败不授予评级，分数仍作为局内成绩展示。以上数值是试玩起点，若过难或无挑战，应按记录调整。

验收：目标进度、波次和结算一致；指定目标不会被护卫替代；每关死亡均失败，限时击落超时未达标失败，生存到时且存活成功；三关对应追击、脱离、目标优先级三种明显不同的决策。

### P5：成绩保存与产品呈现

目标：让玩家知道已完成什么、下一步玩什么。

- [ ] **P5-01 制作正式首页与选关。** 首页提供开始/继续、教学、设置、关于；选关显示目标、解锁状态与最佳成绩。第一关默认解锁，通关依次解锁；最后一关显示首组任务完成，并可选关重玩。结算成功后提供下一关。
- [ ] **P5-02 保存进度。** 在 `user://` 保存存档版本、教学完成状态、已解锁关卡、各关最佳分数/评级与设置；关卡使用稳定 ID。通关或设置变更时保存；读写失败给出可理解提示，不阻断游玩；旧存档缺少新增字段时使用默认值，损坏存档保留备份后恢复默认数据。
- [ ] **P5-03 补齐设置与说明。** 提供音乐/音效音量、震动强度、重玩教学；关于展示作品信息和实际使用素材的署名。提供确认后重置进度的入口，避免误触清空。
- [ ] **P5-04 统一呈现。** 为任务、按钮、警告和结算统一文案与视觉层级；首轮沿用现有英文界面并修正语法、拼写及命名，中文本地化后续单独安排。统一正式游戏名称与品牌显示，去掉面向玩家的开发占位信息。

验收：通关、重启、选关和下一关衔接正确；低成绩不覆盖最佳成绩；设置重启后保留；无存档、字段缺失、损坏存档均能进入游戏；首页所有可见按钮可用，无空页面。

### P6：发布验证

目标：确认发布构建与实际设备上的体验完整。

- [ ] **P6-01 设备与触控检查。** 在至少一台实际 iPhone 上完成教学和三关；检查刘海/灵动岛安全区域、小屏文字、多点触控与前后台切换。若发行支持 iPad，补做实际 iPad 验证；模拟器检查不能代替真机结论。
- [ ] **P6-02 稳定性与性能。** 在高敌机/导弹/特效压力场景记录帧率、卡顿和设备情况；连续游玩至少 20 分钟、重试至少 10 次，检查残留对象、音频、内存持续增长与崩溃。以主要测试设备稳定接近 60 FPS 为目标，达不到时记录瓶颈并修复或明确性能档位。
- [ ] **P6-03 核对发布配置与商店内容。** 检查正式名称、图标、启动页、版本、导出资源与开发功能隔离；截图及描述准确反映已实现内容；隐私与素材声明以实际行为和授权为依据。审核原文尚未提供，不预先归因具体条款。
- [ ] **P6-04 发布验收记录。** 汇总已通过与未通过项、构建标识、设备、系统版本和已知问题，制作从首次进入到结算的完整演示。用户实际授权提交后再执行商店上传与提交；此计划不包含自动发布授权。

验收：没有阻断开局、教学、通关、重试、存档或返回首页的问题；发布设备检查有证据；关键未通过项修复后复测。不要把“已导出”当作“已发布验证完成”。

## 4. 验证与变更管理

自动检查优先覆盖战斗状态、刷怪名额、胜负条件、波次转换、成绩冻结、存档读取与最佳成绩合并。使用与项目匹配的 Godot/LimboAI 构建，并按需运行现有触屏/HUD 集成场景；引擎不可用或测试失败时记录实际结果，不宣称通过。

每轮修改只运行与改动相关的检查；涉及控制、场景切换或 HUD 时补做输入回归。视觉、手感和性能使用试玩记录，不编写仅复制实现的测试。

修改关卡数值、按钮布局、评级规则或阶段顺序时，在实施记录中写明原方案、调整方案、理由与验证。新增阶段外功能需先记录范围调整；避免在手感未确认前批量制作关卡。
